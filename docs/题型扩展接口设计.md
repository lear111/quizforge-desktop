# 题型扩展公共接口设计（草案 v1）

> 状态：目标契约。2026-10-05 已实现 HTML SDK 2 两页面、独立默认 JSON、基础 QF 页面能力、同步 ctx.reportResult，以及共享 HTML 编辑外壳和正式编辑的 QF.bank / navigation / sources 接口；单选、多选已迁移。AI、异步评分和评价持久化仍为设计目标。具体已实现接口以 [SDK 2 开发说明](../extensions/SDK_README.md) 为准。

## 1. 开发者需要编写什么

扩展提供编辑页、练习页和题型逻辑。默认题卡样式、富文本组件、保存、作答轮次、白板、历史、AI 配置及统计由应用提供。

```text
my-question-type/
├── manifest.json        身份、版本、入口和所需能力
├── default.json         默认题目，采用题库中单条 Question 的 JSON 结构
├── editor.html          编辑界面
├── practice.html        练习界面，兼用于草稿、历史、网页预览
├── type.js              校验、判分、小题定位
└── style.css            可选的专用样式
```

复杂页面可以增加自己的 JS/CSS 文件；主程序负责资源加载。生成后的生命周期适配脚本和规则包装由 SDK/打包器提供，题型作者不必逐项实现旧协议。本次发行不加载旧 SDK 1 包；旧题库数据仍保留。

编辑页管理题目数据；练习页管理用户答案和展示。提交调用判分，重试开始新的作答，重试本身不调用判分。开发者可以使用默认按钮，也可以为自定义按钮绑定同一个 SDK 动作。

### 1.1 默认题目 JSON 与题库结构一致

默认展示内容放在 default.json，HTML 保存布局、标签与组件容器。manifest 使用拟定字段 `defaultQuestion: "default.json"` 指向模板；宿主加载并校验，SDK 不再要求开发者写 defaults() 来组装默认题目。

default.json 对应 `.qbank` 的 bank.json 中 `questions[]` 的一条完整 Question，沿用 id、type、prompt、payload、answerSpec、scoreSpec、evaluationSpec、analysis、stimulusRefs、sourceRefs 等字段。编辑器修改同一个数据模型，保存时保持字段和内容结构一致；不另设一套展示字段再手工转换。外部题型仍使用现行 EXTENSION 的 payload/answerSpec 包装，其 data 结构同样直接沿用模板。

以现有内置单选题的数据结构为例：

```json
{
  "id": "q_template",
  "type": "SINGLE_CHOICE",
  "stimulusRefs": [],
  "prompt": { "kind": "TEXT", "text": "下列哪个选项正确？" },
  "payload": {
    "kind": "CHOICE",
    "options": [
      { "id": "opt_template_a", "content": { "kind": "TEXT", "text": "选项 A" } },
      { "id": "opt_template_b", "content": { "kind": "TEXT", "text": "选项 B" } },
      { "id": "opt_template_c", "content": { "kind": "TEXT", "text": "选项 C" } },
      { "id": "opt_template_d", "content": { "kind": "TEXT", "text": "选项 D" } }
    ]
  },
  "answerSpec": { "kind": "CHOICE", "correctOptionIds": ["opt_template_a"] },
  "scoreSpec": { "defaultMaxScore": 1 },
  "evaluationSpec": null,
  "analysis": { "kind": "TEXT", "text": "在此编辑答案与解析，也可使用标准富文本内容。" },
  "sourceRefs": []
}
```

一致指字段结构和数据含义一致，不要求 ID 或资源地址原样复制。每次新建题目，宿主深复制模板、生成题目/选项/小题的新稳定 ID，并同步改写 answerSpec 等引用；加载已有题目时保留原 ID。已有题目以题库数据为准，不用模板覆盖；更新扩展的 default.json 只影响后续新建题目。

默认图片、富文本及共享材料需在包中声明资源和材料依赖，由宿主导入并改写引用；不能把开发者电脑上的绝对路径写入模板。富文本沿用标准内容结构，不能另存一个裸 HTML 字段来代替题库协议。练习页仍只获得当前模式允许的题目投影，不能通过自行读取 default.json 取得当前实际题目的参考答案。

新增流程：读取模板 → 校验结构与引用 → 复制并分配身份/资源 → 编辑同一模型 → 保存到 bank.json。开发预览可以使用模板数据；已有题目、用户作答、评分结果、草稿和历史分别由宿主管理，不混入默认题目文件。

## 2. 公共调用约定

### 2.1 返回值

涉及宿主读写、AI、提交、评分的调用统一返回 `Promise<Reply<T>>`：

```ts
type Reply<T> =
  | { ok: true; data: T }
  | { ok: false; error: {
      code: string;
      message: string;
      retryable: boolean;
      requestId?: string;
    }};
```

错误码用于程序判断，message 用于用户展示；message 不包含密钥、授权头或原始服务端响应。扩展可以显示自己的错误提示；未处理的提交错误由宿主统一显示。SDK 初始化和脚本语法错误走加载错误界面，不伪装成业务返回值。

题型声明、监听订阅和纯页面组件使用本地接口，不强制套用 Promise；组件必须返回释放方法。公共错误还包括 CAPABILITY_DENIED（无权限）、READ_ONLY（只读）、INVALID_INPUT（输入无效）和 STORAGE_FAILED（保存失败）。

每次调用绑定宿主创建的扩展身份、页面模式及当前对象范围。扩展不自行提供 workspaceId、sessionId、attemptId、授权令牌或其他题目的 ID 来扩大访问范围。

### 2.2 模式与订阅

`QF.host.getContext()` 返回只读上下文；`QF.host.subscribe(listener)` 返回取消订阅函数。上下文至少包含：

```ts
type HostContext = {
  mode: "EDITOR" | "PRACTICE" | "DRAFT" | "HISTORY" | "PREVIEW";
  questionId: string;
  capabilities: {
    editQuestion: boolean;
    editAnswer: boolean;
    submit: boolean;
    retry: boolean;
    aiGenerate: boolean;
  };
};
```

状态订阅通知编辑数据、已保存答案、提交状态、结果和模式变化。SDK 管理重复绑定与卸载清理；业务作者只处理自己增加的监听器。只读限制由宿主在每次调用时检查，隐藏或禁用按钮只是显示层措施。

## 3. 接口总表

| 接口（拟定） | 用途 | 写入正式数据的范围 |
| --- | --- | --- |
| `QF.host.getContext / subscribe` | 模式、能力和状态更新 | 无 |
| `QF.editor.getData / update / save` | 读取、修改、刷新当前编辑草稿 | 内存编辑草稿；正式写入通过 QF.bank.save |
| `QF.bank.save` | 正式编辑外壳保存整个题库，先 flush 当前页 | 宿主调用现有题库文件写入服务 |
| `QF.navigation.goTo / previous / next` | 正式编辑会话内切题 | 切换当前题目；先等待编辑草稿完成 |
| `QF.sources.list / add / remove / open` | 当前编辑题目的来源展示与操作 | add/remove 修改草稿；open 不修改来源身份 |
| `QF.content.render / mountEditor` | 显示或编辑标准富文本内容 | 编辑结果交回所属草稿/答案 |
| `QF.content.markers.mount` | 正文标记、空位、点击弹层、定位 | 由回调更新题目或答案 |
| `QF.answer.get / update / flush` | 当前作答及缓冲保存 | 当前活动作答 |
| `QF.practice.getQuestion / submit / retry / getResult` | 读取页面题目、提交、重试、读取已保存结果 | 当前练习轮次 |
| `QF.ai.getStatus / generate / cancel` | 统一 AI 调用、状态、取消 | 不直接保存评分 |
| `ctx.reportResult` | 判分回调向应用报告评分和评价 | 先暂存，宿主校验后原子提交 |
| `QF.ui.mountActions / notify` | 默认按钮、提示、默认卡片样式 | 通过对应动作接口执行 |
| `QF.ids.create` | 编辑时创建稳定的小题/选项 ID | 随编辑草稿保存 |

`type.js` 通过 `QF.defineQuestionType({validate?, targets?, grade})` 声明题型逻辑，默认数据统一从 manifest 指定的 default.json 加载。普通类型的复制、快照、空答案判断等由公共适配器生成；特殊数据结构需声明 ID、引用及内容字段，必要时提供明确的覆盖函数，宿主不能猜测任意自定义字段的含义。小题定位使用稳定 ID，显示编号由宿主计算，锁定提示不参与计分和待答编号。

## 4. AI 接口：全局配置是唯一入口

### 4.1 配置权和状态

AI 服务商、连接地址、模型、凭据、超时及请求限制在应用设置中统一配置。扩展不得要求填写另一份 API Key，不接收凭据，也不能在调用参数中指定 baseUrl、provider、model 或任意 HTTP 请求。

`QF.ai.getStatus()` 返回是否可用及可展示的原因码，例如未配置模型、缺少凭据、当前模式不允许。该调用不发模型请求，也不承诺后续网络调用一定成功。

扩展可以提供任务提示词及题型输入；温度、输出长度等生成选项只允许宿主公开的有限范围，缺省采用应用配置。扩展声明所需的 `ai.generate` 能力，应用统一决定是否启用。第一版只在用户主动操作（包括提交触发的判分）中调用，不因页面挂载、滚动或历史回放自动请求 AI。

### 4.2 请求

```ts
type AiGenerateRequest = {
  context: {
    include: Array<
      "prompt" | "referenceAnswer" | "analysis" | "gradingRules" | "answer"
    >;
  };
  input?: Record<string, unknown>;  // 额外的当前题型任务数据
  prompt: string;                    // 开发者自定义任务提示词
  output?: { format: "text" | "json"; schema?: JsonSchema };
  options?: { temperature?: number; maxTokens?: number };
};
```

题干、解析、参考答案、评分细则及作答由宿主根据当前范围装配；input 只补充题型任务数据，不覆盖宿主的满分、题目身份和已冻结答案。富文本由宿主解析为文字及可支持的媒体输入；外部地址不作为自动下载来源，图片是否可发送取决于应用配置模型的能力，不支持时返回明确错误。

- 编辑模式使用当前编辑草稿；AI 生成的内容需经过 editor.update/save 才写入题库。
- 判分使用提交时冻结的题目、规则和答案，不读取调用过程中变更的编辑内容。
- 练习页面在提交前不获得参考答案、解析和评分细则；包含这些内容的判分上下文仅交给宿主启动的判分执行环境。
- 解释/评价请求使用已提交的作答。解释请求成功不会改变分数。
- 历史和网页预览只显示既有结果，不调用 AI。开发预览默认使用模拟返回；显式测试真实 AI 时使用相同全局配置和能力检查。

自定义 prompt 作为任务指令，题目、解析、答案作为结构化资料加入请求。应用自己的模型和连接控制不由提示词决定。模型输出不作为脚本执行。

### 4.3 响应与取消

```ts
type AiOutput = {
  requestId: string;
  text: string;                     // 大模型输出文字
  json?: unknown;                   // 请求 JSON 时经解析/Schema 校验的结果
  model: { provider: string; name: string };
};
```

文本输出不保证具有分数字段。请求 JSON 时，不能因为模型返回成功就假定结构有效；无法解析或不符合指定结构时返回 AI_PROVIDER_INVALID_RESPONSE。text 用于显示原始输出，json 用于可靠地提取评分/评价字段。仅返回可展示的模型信息，不返回连接凭据。

`QF.ai.generate(request, {signal?})` 支持取消信号；调用进行中，调用方可从 SDK 的 request-start 事件取得 requestId，调用 `QF.ai.cancel(requestId)`。取消仅限本扩展本范围的请求。退出判分范围时宿主自动取消；若服务商无法终止已发请求，宿主丢弃迟到响应，不能承诺取消后不产生模型费用。

### 4.4 错误码

| code | 含义 | 是否适合重试 |
| --- | --- | --- |
| AI_PROVIDER_NOT_CONFIGURED | 未配置服务商/模型 | 配置后重试 |
| AI_PROVIDER_CREDENTIAL_MISSING | 所需凭据缺失 | 配置后重试 |
| AI_PROVIDER_AUTHENTICATION_FAILED | 凭据认证失败 | 修复配置后重试 |
| AI_PROVIDER_RATE_LIMITED | 服务商限流 | 稍后重试 |
| AI_PROVIDER_TIMEOUT | 请求超时 | 可由用户重试 |
| AI_PROVIDER_UNAVAILABLE | 网络或服务暂不可用 | 可由用户重试 |
| AI_PROVIDER_INVALID_RESPONSE | 响应、JSON 或输出结构无效 | 根据具体原因重试 |
| AI_REQUEST_CANCELLED | 调用已取消 | 用户需要时重新发起 |
| AI_CAPABILITY_UNAVAILABLE | 当前模式或扩展未获得调用能力 | 切换允许的模式或配置能力 |
| AI_INPUT_UNSUPPORTED | 输入媒体或选项不受支持 | 修改输入后重试 |

前七个 AI_PROVIDER_* 码沿用现有 Core 命名；其余为本草案新增。未配置模型时直接返回错误，不访问网络，不使用扩展自选模型作后备。

### 4.5 防止绕过全局配置需要执行环境限制

只提供一个 AI 方法无法阻止任意网页脚本另行联网。两页面扩展的运行环境必须同时限制外部 fetch/XHR、WebSocket、远程脚本、表单/导航、资源出网及其他网络通道；只加载包内许可资源和宿主提供的内容。页面桥接只暴露按范围检查的 SDK 能力，不能暴露通用 HTTP、任意 Java 调用、文件读取或设置凭据的对象。

现有编辑/开发预览页已有 connect-src 'none' 等 CSP，但现行扩展脚本机制并非已验证的第三方隔离沙箱。上线两页面 SDK 前必须完成页面、判分环境和桥接边界验证；不得把“没有提供 apiKey 参数”当作已实现防绕过。这是本接口要求的实现门禁。

## 5. 评分接口：显示分数与保存分数是两个动作

### 5.1 谁能报告评分

练习页调用 `QF.practice.submit()`；宿主冻结本次答案、题目和满分，启动 `grade(ctx)`。ctx 是一次提交专用、不可伪造的能力对象，提供只读的 question、answer、maxScore、targets，以及范围内的 ai 和 reportResult。

`ctx.reportResult(result)` 是题型向应用输出评分的正式接口。普通页面不能随时修改总分，历史页不能用它重新判分。默认客观判分、自定义规则判分和 AI 判分都通过同一个结果契约提交。

### 5.2 评分结果

```ts
type GradeReport = {
  score: number | null;
  feedback?: {
    summary?: string;               // 总体评价
    comments?: Array<{ targetId?: string; text: string }>;
    criteria?: Array<{ id: string; score: number; comment?: string }>;
    content?: QuestionContent;      // 可选的标准富文本评价
  };
  items?: Array<{ targetId: string; score: number | null; feedback?: string }>;
  aiRequestId?: string;             // 可关联本次成功的宿主 AI 请求
};
```

满分来自冻结的题型/评分规则，由宿主补充；扩展不通过结果修改 maxScore。ctx.reportResult 只暂存结果，返回 ResultAccepted；grade 回调成功结束后，宿主完成最终保存。回调抛错、取消或超时，暂存结果作废，避免“已保存评分但回调失败”的不一致。

```ts
type ResultAccepted = { staged: true };
// 普通规则可以同步返回；AI 判分可以异步返回。
type GradeCallback = (ctx: GradingContext) =>
  Reply<ResultAccepted> | Promise<Reply<ResultAccepted>>;
```

grade 必须返回 reportResult 的成功结果或失败 Reply。失败 Reply 会终止提交，不能仅因为 Promise 正常结束就视为成功。没有报告结果返回 GRADING_RESULT_MISSING；抛出未处理异常返回 EXTENSION_GRADING_FAILED；宿主判分期限耗尽返回 GRADING_TIMEOUT。ResultAccepted 仅确认暂存，练习页的 submit 成功返回值才表示正式落盘。

宿主必须检查：

1. score 是有限数且位于 0～maxScore；null 表示未评分，不能转换成零分。
2. 若提供 items，须覆盖所有待评分目标；提示/锁定目标不能写分，ID 必须来自冻结目标；子项分数边界、总和与父题分数一致。允许只报告整题分数，宿主不凭空编造逐小题反馈。
3. criteria 如提供，必须符合冻结评分细则的维度及范围；维度可加总与否由规则明示，不能一律假定可加总。
4. 富文本资源必须属于本次范围；文字和模型输出不作为任意 HTML/JavaScript 执行。
5. aiRequestId 如提供，必须属于当前判分并成功完成；扩展不能伪造 AI 来源。宿主记录题型版本、判分来源、模型信息、请求关联和时间，不保存凭据。
6. 同一判分只能报告一个最终结果；重复的相同调用幂等，不同结果返回 RESULT_ALREADY_REPORTED。
7. 保存时再次验证轮次、题目版本、答案版本和取消状态；迟到结果返回 STALE_GRADING_CONTEXT，不写到下一题或下一次作答。

第一版内部结果兼容现行 CORRECT / INCORRECT / UNSCORED：满分映射为 CORRECT，非满分映射为 INCORRECT，score:null 映射为 UNSCORED；分数与评价独立显示，非满分可以带部分得分。将来若增加新的结果分类，另行升级协议。

### 5.3 AI 判分示例

```js
// 目标接口示例，尚未实现。
QF.defineQuestionType({
  async grade(ctx) {
    const reply = await ctx.ai.generate({
      context: { include: ["prompt", "referenceAnswer", "analysis", "gradingRules", "answer"] },
      prompt: "依据评分规则评价本次作答，返回 score 和 comment；不得超过题目满分。",
      output: {
        format: "json",
        schema: {
          type: "object",
          required: ["score", "comment"],
          properties: { score: { type: "number" }, comment: { type: "string" } },
          additionalProperties: false
        }
      }
    });
    if (!reply.ok) return reply;
    return ctx.reportResult({
      score: reply.data.json.score,
      feedback: { summary: reply.data.json.comment },
      aiRequestId: reply.data.requestId
    });
  }
});
```

扩展决定是否在自己的练习页显示分数、评价或两者；评分和反馈仍以宿主确认保存的 Result 为准。隐藏分数不会让统计忽略该题；只显示一个未经 reportResult 接收的数值，不构成正式评分。AI 生成成功与评分提交成功是不同返回值。

`QF.practice.getResult()` 返回 `Reply<SavedResult | null>`；当前作答尚未提交时为 null。当前 SDK 的 `submit()` 返回 `Reply<{confirmationRequired:boolean,result:公开结果|null}>`：弹出确认框不表示提交完成；直接提交完成后 `result` 与 `getResult()` 一致。下列 SavedResult 是含异步评价及 provenance 的目标完整结构，尚未全部接入；当前已实现接口以 [公共 UI 接口](../extensions/PUBLIC_UI_API.md#5-作答分值和结果) 为准：

```ts
type SavedResult = {
  attemptId: string;                // 只读标识，不可用于跨范围调用
  score: number | null;
  maxScore: number;
  status: "CORRECT" | "INCORRECT" | "UNSCORED";
  feedback?: GradeReport["feedback"];
  items?: GradeReport["items"];
  provenance: {
    extensionId: string;
    extensionVersion: string;
    ai?: { requestId: string; provider: string; model: string };
  };
  submittedAt: string;              // 宿主生成的 ISO 8601 时间
};
```

provenance、满分、状态和时间由宿主生成。AI 的原始输出通过 generate 返回；要在历史中展示的评价必须写入 feedback，不能依赖当前页面保存的模型输出变量。宿主不默认永久保存完整模型请求和响应。

### 5.4 提交过程与失败

```text
可作答 → 提交并冻结输入 → GRADING → 校验暂存结果 → 原子保存 → SUBMITTED
                             ↓
                        错误/取消 → 保留原作答，可再次提交
SUBMITTED → retry → 新的可作答轮次 → 再次 submit 时重新判分
```

GRADING 期间禁止修改答案、重复发起另一判分和重试；重复点击同一次 submit 复用同一宿主操作。切题/关闭须先取消或完成该判分。模型调用不在数据库写事务中等待：先取得冻结输入，网络调用在事务外执行，最终用短事务校验并保存。

最终事务同时保存本次答案、评分/反馈、版本、草稿快照和尝试记录，随后发布 Result 更新统计与题卡。存储失败返回 STORAGE_FAILED，保留可重试状态，不产生假的已提交结果。取消后可再次提交；重试不会覆盖已有历史尝试。AI失败不静默记零分；用户显式选择暂存为未评分时 score:null，或使用题型事先声明的规则判分路径。

历史保存已确认的评分与评价，回放不重新请求模型。新增反馈和模型来源字段需要持久化设计，不能只存在于页面变量中。

## 6. 编辑、内容与作答接口

- `QF.editor.getData()`：当前完整编辑草稿，含该题的参考答案/解析。
- `QF.editor.update(patch)`：更新声明的题型字段；身份、资源归属和编辑事务由宿主控制。
- `QF.editor.save()`：等待页面缓冲完成并刷新编辑草稿；`QF.bank.save()` 再经宿主验证并写入正式题库。界面移除/切题前使用同一个 flush 屏障。
- `QF.answer.get/update/flush()`：管理当前用户答案，不授予标准答案读取权限；等待保存确认才认为落盘。
- `QF.practice.getQuestion()`：读取当前模式可公开的题目数据及稳定小题目标；提交前移除参考答案、解析、评分细则等受限字段，不把完整题目先交给页面再依靠隐藏元素限制访问。
- `QF.content.render(container, content)`：渲染标准 TEXT/RICH/DOCUMENT，资源由宿主解析。
- `QF.content.mountEditor(container, {value, formatting, onChange})`：公共富文本输入，formatting 控制格式工具栏；内容与资源交回所属编辑/作答事务。
- `QF.content.markers.mount(container, {pattern, targets, onActivate})`：保留文章格式替换标记、处理跨文本节点标记；空位选项弹层、定位、状态更新和释放由公共组件管理，具体答案回调由题型绑定。
- `QF.ui.mountActions(container)`：可选的默认提交/重试按钮，直接执行宿主动作；专用按钮可调用相同方法。
- `QF.ui.configure(patch)` / `getConfiguration()`：已实现的同步公共 UI 显示配置。编辑可选择保存、增删复制、来源、大纲等；练习可选择题卡外壳、题目信息、提交、重试、确认、来源、大纲与白板工具。上一题/下一题不可关闭。参数与示例见 [SDK 2 说明](../extensions/SDK_README.md#32-扩展选择公共-ui)；未声明的项默认显示，配置不改变权限或持久化事务。
- `QF.bank.getState/addQuestion/duplicateQuestion/deleteQuestion`、`QF.navigation.getState/goTo/previous/next`、`QF.sources.list/open/add/remove`：已实现公共题目编辑和浏览操作，按当前会话身份校验；写入仅开放给编辑会话。
- `QF.learning.getMode/setMode/toggleMode`、`QF.whiteboard.getState/setTool/undo/redo/clear/setAppearance/setZoom/zoomBy`：已实现正式练习和历史的模式切换与白板工具，复用原模型、保存及只读规则。用 `QF.ui.mountControls` 标记可在绘画时点击的自定义工具区；详细参数见 [公共 UI 功能接口](../extensions/PUBLIC_UI_API.md)。
- `QF.layout.configure/getConfiguration/getState`：已实现题卡逻辑宽度、可见最大宽度、初始对齐和浏览区留白。题卡高度自然增长，编辑与预览使用普通页面排版，桌面练习使用临时阅读视口。已保存草稿的几何与历史快照优先，不因页面声明或热更新重置。后续展示与功能编辑优先放在拓展中，宿主提供通用执行、状态和权限边界。详见 [布局接口](../extensions/PUBLIC_UI_API.md#8-题卡与浏览区布局)。
- `QF.ui.notify({level, message})`：范围内的提示，不改变答案或评分。
- `QF.ids.create(prefix)`：编辑草稿新增对象的稳定 ID，不能用显示编号作为对象身份。

本节确定能力边界；HTML 属性绑定、组件具体参数、patch 路径与媒体字段 Schema 在实施前逐项补齐。SDK 负责富文本资源、事件释放和不同模式的行为适配，扩展不接管文件路径、白板存储或历史数据库。

## 7. 模式权限

| 能力 | 编辑 | 正常练习/草稿 | 判分上下文 | 历史 | 网页预览 |
| --- | --- | --- | --- | --- | --- |
| 读取题干及页面公开数据 | 是 | 是 | 冻结数据 | 冻结数据 | 公开数据 |
| 修改题目及参考答案 | 是 | 否 | 否 | 否 | 否 |
| 修改用户答案 | 否 | 可作答状态 | 否 | 否 | 否 |
| 提交/重试 | 否 | 由状态决定 | 宿主管理 | 否 | 否 |
| 调用 AI | 用户主动生成 | 已提交后的主动解释 | 本次判分 | 否 | 否 |
| 读取完整参考答案/评分细则 | 是 | 提交前否 | 是 | 按回放公开 | 按预览规则公开 |
| 报告评分 | 否 | 页面无独立权限 | 是 | 否 | 否 |
| 修改白板 | 否 | 仅草稿模式 | 否 | 否 | 否 |

网页 Hub 首版仅提供预览，不提供 AI 请求代理、正式作答和评分提交。草稿/历史仍复用练习页，白板和历史导航按键属于外层宿主。

## 8. 现状与实施顺序

| 能力 | 当前代码 | 下一阶段 |
| --- | --- | --- |
| 全局 AI 设置、凭据存储、服务商接口 | 已有 AiSettingsService / AiProviderResolver / AiProvider | 增加范围明确的异步扩展桥，不新增扩展自有设置 |
| AI 错误分类 | 已有七个 AI_PROVIDER_* 错误码 | 增加取消、能力、输入类型错误 |
| 外部题型评分 | 现行 grade 同步调用，检查冻结满分与分数范围 | 新增异步判分上下文、结果上报及幂等提交 |
| 模型评价与来源持久化 | 现行扩展 Grade 主要接收 status/score/maxScore | 明确反馈、模型来源及请求关联字段，保存并回放 |
| 七型编辑/练习/草稿/历史 | 已使用公共扩展宿主和版本化题卡 | 两 HTML 页面及公共组件适配，隐藏旧生命周期协议 |
| 第三方脚本隔离 | 已有部分 CSP；未证明完整隔离 | 先验证隔离/能力桥，满足统一 AI 入口约束 |

建议实施顺序：

1. 确认本文的模式、数据归属、AI输入/输出、错误码、评分与提交契约。
2. 实现公共宿主桥及执行环境限制；接入现有全局 AI 配置。
3. 实现异步判分、评分/评价持久化与只读历史回放。
4. 提供两页面模板及富文本/标记组件，用一项 AI 主观题走通编辑、作答、提交、失败重试和历史。
5. 对既有扩展增加适配，保留旧题库、规则版本和历史兼容；再迁移内置题型。

第一版优先文本/JSON AI 输出、完整请求返回、不做流式输出；图像输入按模型能力单独定义。开发者先依照冻结后的契约开发，不把本文草案示例当作现行可运行 API。
