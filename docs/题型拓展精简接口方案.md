# 题型拓展精简接口方案

更新日期：2026-10-07。

状态：SDK 2.3 已实现第一版统一加载、保存、操作入口，并迁移八个题型、各附带真实 `.qbank` 样例。本文保留完整目标设计；**已实现的具体参数和未开放能力以 [SIMPLE_PAGE_API](../extensions/SIMPLE_PAGE_API.md) 为准**。直接分数提交、任意尝试 ID、小题定位和编辑／练习模式请求切换仍待后续接入，不能将本草案所有接口当成已可调用。

文档整理：当前判断题包为 2.3.1、11 文件手写模板，其余七型为 2.3.0。新开发见 [开发指南](../extensions/DEVELOPMENT_GUIDE.md)。下文 reason、资源访问与 submitScore 等字段/示例属于目标结构，实际加载字段和公开命名空间查现行参考。

本轮范围补充：独立图片、视频加载／播放公共接口暂缓，只预留设计位置。现有富文本文档中已经支持的图片内容仍按既有资源机制处理。八个题型的样例题库已纳入打包和原生安装校验；网页预览读取样例，并提供下载，题型库管理界面后续实现。

## 1. 已确认的职责和边界

| 项目 | 拓展负责 | 应用负责 |
| --- | --- | --- |
| 页面 | 编辑页和练习页的 HTML、CSS、交互 | 加载入口、页面切换、生命周期、权限 |
| 题卡 | 可在样例拓展中提供默认布局，也可完全不使用 | 不强制插入可见题卡、白色背景、边框或阴影 |
| 布局 | 决定初始位置、尺寸和页面排列 | 执行几何定位，保存、恢复白板上的移动位置 |
| 题目 | 定义自己的数据结构、默认数据、校验和评分规则 | 类型识别、身份管理、验证、持久化 |
| 作答 | 输入、选项同步、结果展示 | 答案保存、尝试状态、评分结果记录 |
| 历史 | 复用练习页显示 | 提供冻结快照，强制只读 |
| 导航 | 可以制作自定义操作 UI | 保留默认上一题／下一题，执行题目与尝试切换 |
| 白板 | 声明是否使用；不得修改内部样式、工具栏或实现 | 默认启用，右上角切换入口、工具、存储和历史恢复 |
| 其他资源 | 使用默认组件或自带实现，处理题型交互 | 统一资源访问、格式约定、权限及持久化 |
| 统计 | 不接管最终统计页面 | 使用已保存的分数汇总，显示最终统计卡 |

白板默认启用：未声明 `useDraft` 或声明为 `true` 均启用；只有显式 `false` 才关闭入口。关闭入口不删除已有白板内容。用户通过应用默认工具调整纸张颜色、纹理等设置仍由应用管理。

练习、草稿和历史使用同一套题目内容。练习模式隐藏白板工具、限制白板交互，保留可见内容和纸张背景；历史中答案和白板内容只读。首次纸张为纯白无纹理，之后恢复保存设置。

## 2. 通信入口

| 入口 | 方向 | 作用 |
| --- | --- | --- |
| `onLoad(context)` | 应用 → 拓展 | 唯一的数据加载入口；首次打开、切题、切换尝试、重试和状态同步 |
| `save(request)` | 拓展 → 应用 | 保存题目修改、未提交答案或正式尝试 |
| `requestAction(request)` | 拓展 → 应用 | 题库管理、导航、模式切换、重试、来源操作 |
| 公共资源访问 | 拓展 ↔ 应用 | 按引用读取、创建、更新资源；具体传输由 SDK 处理 |
| `submitScore(request)` | 拓展 → 应用 | 可选的后续评分入口，与正式提交共用结果校验和存储逻辑 |

组件挂载、DOM 装饰、视频进度监听、释放等是 SDK 的页面内方法，不需要为每种 DOM 操作新增宿主通信接口。少量入口不代表任意操作都自动支持：所有操作名称、参数和权限必须列入白名单。

## 3. 公共请求与返回

写入与操作请求具有以下公共字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `requestId` | string | SDK 生成；同一请求重发使用相同 ID，供应用去重 |
| `contextId` | string | 应用生成的页面上下文标识；绑定拓展、题目、尝试和模式 |
| `revision` | integer | 当前上下文的数据版本；应用检查冲突 |

拓展不能提供任意数据库表名、SQL、文件路径，不能通过请求中的 ID 扩大访问范围。目标题目、目标尝试等导航参数只能选择应用已允许访问的对象。

```ts
type Reply<T> =
  | { ok: true; data: T }
  | {
      ok: false;
      error: {
        code: string;
        message: string;
        issues?: Array<{ path: string; message: string }>;
      };
    };
```

SDK 排队处理同一上下文的写入，使用已确认的最新版本发送下一项，避免快速连续输入产生自冲突。跨页面或外部修改产生的冲突由应用拒绝。保存失败时保留页面输入，不显示虚假的已保存状态。

重试、正式提交等写操作必须去重。超时不代表回滚。当前实现提供页面上下文内最多 1024 项内存回执缓存，并检查 revision；不提供跨页面关闭或应用重启的永久请求查询。跨会话持久去重与保留期限属于后续设计，实际调用约定见现行接口第 3 节。

## 4. 唯一加载入口

### 4.1 上下文结构

```json
{
  "contextId": "context_example",
  "revision": 12,
  "reason": "initial",
  "mode": "practice",
  "learningMode": "practice",
  "question": {
    "id": "q_example",
    "type": "publisher.example",
    "dataVersion": 1,
    "data": {},
    "maxScore": 10
  },
  "attempt": {
    "id": "attempt_example",
    "status": "draft",
    "answer": {},
    "result": null
  },
  "reference": null,
  "permissions": {
    "editQuestion": false,
    "writeAnswer": true,
    "submit": true,
    "retry": false,
    "submitScore": false,
    "manageQuestions": false,
    "manageSources": false
  },
  "navigation": {
    "index": 0,
    "total": 5,
    "previousAvailable": false,
    "nextAvailable": true,
    "previousAttemptAvailable": false,
    "nextAttemptAvailable": false,
    "targetId": null
  },
  "sources": [],
  "resources": []
}
```

| 字段 | 约定 |
| --- | --- |
| `reason` | `initial`、`questionChanged`、`attemptChanged`、`modeChanged`、`retry`、`stateChanged` |
| `mode` | `edit`、`practice`、`history`、`preview`；历史和预览只读 |
| `learningMode` | `practice` 或 `draft`；不改变答案身份 |
| `question.data` | 拓展声明的题目结构，JSON 文件与数据库都转换到这一结构 |
| `question.maxScore` | 应用根据题型声明校验后的整题满分，不由页面自由覆盖 |
| `attempt` | 编辑页为 `null`；其他页面加载允许查看的尝试 |
| `attempt.answer` | 拓展声明的答案结构；初始空答案也由声明确定，不能假设所有题型都是 `{}` |
| `attempt.result` | 未评分／未提交可以为空；有结果时包括 `score`、`maxScore` 和可选反馈、小题结果 |
| `reference` | 标准答案、解析等受保护内容；编辑或允许查看结果时提供，未允许时为 `null` |
| `navigation.targetId` | 大纲定位到的小题目标；拓展负责页面内滚动或聚焦 |
| `sources` | 可展示、可打开的来源摘要，不暴露任意路径 |
| `resources` | 当前上下文允许访问的资源描述；大内容通过引用按需获取 |

历史使用当时的题目、资源、答案、评分和白板快照，以及关联的拓展／数据版本。不得直接用当前题库内容替代旧快照。

### 4.2 校验与渲染

1. 应用识别题型和数据版本，找到拓展；缺失时保留原数据并显示错误。
2. 应用检查公共外壳和该模式的数据结构。拓展定义 Schema 和业务规则，应用在可终止的受限环境中执行。
3. 应用按权限生成展示数据，隐藏未允许查看的标准答案和解析。
4. SDK 调用 `onLoad`；拓展更新页面和必要组件。
5. 拓展完成渲染后返回成功，或返回明确错误。应用保留统一的失败、重载和导航能力。

完整编辑数据与练习公开数据需要各自明确的校验契约。允许参考答案为空不等于绕过 Schema；参考答案不能靠 CSS 隐藏在未提交页面中。

`onLoad` 接收逻辑上完整的上下文；底层可以分块传输资源，但不能要求开发者拼装消息。快切时 SDK 标记旧加载失效，拓展停止旧异步任务，迟到结果不能覆盖当前页面。

同题型优先复用页面更新数据；不同题型由应用选择对应入口。同一个加载接口不承诺一定保留同一个 iframe，但禁止用整页空白重载作为必要的业务步骤。

### 4.3 页面能力与初始几何

拓展可在初始化声明或加载完成返回值中提供页面配置；具体调用名称待确定。

```json
{
  "useDraft": true,
  "initialLayout": {
    "horizontalAlign": "center",
    "verticalAlign": "center",
    "width": 820,
    "height": "auto"
  }
}
```

- `useDraft` 缺省为 `true`；应用显示右上角入口并执行切换。
- `initialLayout` 可省略。几何应用于拓展内容区域，不代表应用绘制题卡。
- 初始几何仅用于没有保存布局的新作答。已有布局／白板视口以保存数据为准；历史恢复快照。
- 几何必须在允许的数值范围内。窗口尺寸、浏览器挂载边界和全局导航仍由应用管理。
- 白板内部 CSS、工具栏、实现和权限不接受拓展覆盖。

## 5. 保存入口

```ts
save({ requestId, contextId, revision, purpose, data }): Promise<Reply<{
  contextId: string;
  revision: number;
  status: string;
}>>
```

| `purpose` | `data` | 可用条件 | 成功后 |
| --- | --- | --- | --- |
| `edit` | `{ questionData, common? }` | 编辑模式且有编辑权限 | 校验并持久化当前题目，返回新版本 |
| `draft` | `{ answer }` | 当前尝试可写 | 保存未提交答案，不创建正式提交，不评分 |
| `submit` | `{ answer, result? }` | 当前尝试可提交 | 校验、评分／接收结果，并冻结正式答案及白板快照 |

`questionData` 对应完整的拓展私有题目数据。`common` 仅接受明确允许编辑的公共字段，例如分值配置、来源引用；不得改题目身份、题型或其他历史记录。

`draft` 不接受分数、标准答案或正式提交状态。答案草稿可以不完整，但仍必须满足结构、引用和权限约束；正式提交允许缺少答案的规则由题型声明。

`submit` 的结果策略由题型声明：规则自动判分，或接受符合权限及格式的外部结果，或保存为未评分。页面不得通过临时提供 `result` 绕过已声明的规则评分路径。

提交事务同时关联答案、结果、题目／资源版本及白板快照。持久化失败不得只保存其中一部分或报告提交成功。调用成功后根据需要发布 `stateChanged` 上下文；普通保存回执不应强制重建表单或丢失光标。

### 5.1 分数约定

| 项目 | 约定 |
| --- | --- |
| `score` | 有限数值或 `null`；零分不等于未评分 |
| 满分 | 来自应用校验并冻结的题目快照 |
| 范围 | `0 <= score <= maxScore` |
| 无分数 | 无评分来源且结果省略时记未评分，不推断为零分 |
| 状态 | 应用生成未评分、满分、非满分等状态，不信任页面直接设置状态 |
| 小题结果 | 可选；目标必须属于当前题目，分值和聚合规则必须与题型契约一致 |
| 评价 | 可选；只按声明格式保存、展示，不作为未经校验的 HTML 执行 |
| 统计 | 汇总已评分部分，同时显示未评分情况；不把未评分伪装成零分 |

数值校验只能保证合法性，不能证明评分逻辑正确。自动评分在应用的受限规则环境执行，页面用于展示结果。

可选 `submitScore({requestId,contextId,revision,score,feedback?})` 仅向允许评分的已提交当前尝试补充结果。历史／预览页面拒绝写入；已评分结果是否允许修订、未评分在统计中如何展示，见待确认项。此接口不重新保存答案，不生成新尝试。

## 6. 操作清单

`requestAction({requestId,contextId,revision,action,params?})` 使用相同身份、权限、版本和去重规则。

| `action` | 参数 | 可用范围 | 行为 |
| --- | --- | --- | --- |
| `addQuestion` | `{type, position: "afterCurrent"}` | 编辑、允许管理题目 | 读取模板，分配身份和引用，插入并加载新题编辑页 |
| `deleteQuestion` | 无 | 编辑、允许管理题目 | 删除当前题目，更新大纲，加载相邻题；最后一题删除后为空题库 |
| `duplicateQuestion` | 无 | 编辑、允许管理题目 | 复制整题，按声明处理内部身份和引用，加载新题 |
| `moveQuestion` | `{beforeQuestionId: string|null}` | 允许管理题目；默认练习大纲也可授予此能力 | 移动当前整张题目；`null` 为移到末尾，同步实际顺序和大纲 |
| `goToQuestion` | `{direction:"previous"|"next"}` 或 `{questionId,targetId?}` | 允许导航的页面 | 完成离开检查，加载目标；下一题在最后一题后进入统计页 |
| `goToAttempt` | `{direction:"previous"|"next"}` 或 `{attemptId}` | 练习／历史 | 查看允许访问的已有记录，不新增、不重评 |
| `returnToCurrentAttempt` | 无 | 练习中正在查看旧尝试 | 恢复当前答案、草稿和权限 |
| `setPageMode` | `{mode:"edit"|"practice"}` | 允许切换的会话 | 加载对应页面；历史不能据此获得编辑权限 |
| `setLearningMode` | `{mode:"practice"|"draft"}` | 启用白板且支持切换 | 保留同一答案和白板，改变交互模式 |
| `retry` | 无 | 练习、允许重试 | 保存／确认当前尝试，创建新的空白作答和白板，再加载 |
| `addSource` | `{link}` | 编辑、允许来源管理 | 应用解析来源并关联当前题目 |
| `removeSource` | `{sourceId}` | 编辑、允许来源管理 | 移除当前题目引用 |
| `openSource` | `{sourceId}` | 允许查看来源的页面 | 应用打开已授权来源；不接受任意 URL 或文件路径 |

目标参数只能指向允许访问的题目／尝试／来源。移动小题大纲时，应用先确定其所属整张题目，不单独移动小题。大纲目标声明中的提示项不占作答编号。

新增和复制不能直接复用模板里的题目身份。拓展私有数据内部的 ID 及关联资源如何复制由声明处理；应用校验结果，不按题型名称写专属分支。

重试不等于评分：已提交的尝试不得重复提交；未提交内容如何归档见待确认项。切换尝试必须保留当前未提交输入，查看旧尝试时强制只读。

## 7. 应用按钮如何收集尚未保存的输入

应用不能通过猜测 DOM 来收集答案。仅有加载和保存接口，不能保证默认导航按钮知道表单中还未调用保存的内容。

建议提供 SDK 生命周期回调 `onBeforeLeave({reason})`，由拓展返回当前待保存的数据：

```ts
type PendingSave = {
  purpose: "edit" | "draft";
  data: object;
};

onBeforeLeave({reason}): Promise<Reply<{pendingSave: PendingSave|null}>>
```

这是页面生命周期，不是新增业务请求入口。SDK 在应用默认导航、切模式、关闭页面和自定义操作请求前收集输入，再用同一个保存入口执行已确定的保存策略。之前的在途保存先完成，禁止把同一次用户操作执行两次。

若编辑保存策略是手动，回调不应暗中执行正式 `edit` 保存；应将内容暂存为会话编辑草稿或阻止离开，等待明确策略。应用收到的临时表单不是已持久化题目。

另提供 `onDispose()` 生命周期，用于释放监听、编辑器和播放器；页面隔离与资源访问撤销仍由应用保证。SDK 不代替拓展清理自建组件。

## 8. 公共资源和白板

| 能力 | 应用通信 | 页面内能力 |
| --- | --- | --- |
| 读取资源 | `read(ref)`：验证作用域和版本，返回文档内容；独立图片／视频接口暂缓 | 当前优先富文本展示 |
| 创建资源 | `create({kind,formatVersion,content})`：暂存并返回作用域内引用 | 当前优先富文本编辑；独立图片导入 UI 暂缓 |
| 更新资源 | `update({ref,revision,content})`：历史版本不可覆盖 | 收集编辑内容 |
| 富文本 | 标准文档结构和按引用读写 | 渲染完成通知、可操作 DOM、组件编辑和释放 |
| 独立图片（预留） | 未来提供专门加载、导入能力，本轮不实现 | 未来支持图片组件；不影响现有文档内图片 |
| 视频（预留） | 资源读取或媒体流 | 播放状态／时间事件，叠加字幕与讲解层 |
| 白板 | 应用自动保存并关联尝试快照 | 应用默认组件，拓展只声明使用与否 |

资源创建／更新先形成可引用的新版本，题目或答案成功保存时关联。旧历史引用不得原地覆盖；失败和未关联资源由应用回收。不可变资源版本的具体发布流程需在实现资源层前确定。

加载上下文和正式保存消息使用引用，不重复携带大图片／视频。应用与 SDK 处理分块、传输大小、校验和取消；对开发者呈现一个完整的读写结果。

富文本渲染到拓展可操作的 DOM 后，拓展可以将 `{{1}}` 替换成选择控件。原文和用户答案分开保存；组件重新渲染后，拓展恢复交互。真正的富文本编辑内部自定义节点需要编辑器提供插件机制，不能保证任意修改编辑器 DOM 都安全。

白板工具栏、纸张设置、拖动缩放、撤销重做均由应用默认组件控制。拓展不通过资源更新接口替换白板内部文档或 CSS。默认按钮的点击不能被白板绘画／拖动事件拦截；题目交互在练习模式下始终可用。

## 9. 拓展声明，不算页面通信接口

| 声明 | 目的 |
| --- | --- |
| 类型标识、版本、编辑／练习入口 | 选择并加载对应拓展 |
| 默认题目、初始答案 | 新建题目、新尝试的初始数据 |
| 样例题库列表 | 为每个题型提供一份或多份可直接加载的展示及验收数据 |
| 题目／公开题目／答案 Schema、数据版本 | 按模式校验，兼容旧数据 |
| 业务校验规则 | 选项存在、标记合法、参考对应关系等 |
| 公开数据投影 | 公开固定提示，保护其他答案和解析 |
| 满分、小题目标及聚合规则 | 大纲编号、定位、复合题评分与统计 |
| 创建／复制的身份处理规则 | 新身份、内部引用、资源引用保持一致 |
| 评分来源和规则 | 自动规则、允许的外部评分或未评分 |
| 数据迁移／旧版本处理 | 不自动覆盖历史，明确兼容策略 |
| 页面配置 | 默认白板、可选初始几何 |

这些声明由应用在安全边界内检查、执行。前端页面自行报告“通过”不能替代应用校验。开发者可以复用 SDK 默认声明工具，但新增题型不应需要修改应用中的题型专属适配器。

### 9.1 复合题导航目标

拓展通过 `targets(question)` 规则返回稳定的小题目标列表，例如：

```json
[
  { "id": "item_a", "label": "阅读理解" },
  { "id": "item_b", "label": "阅读理解" }
]
```

- 应用按题目顺序及目标列表顺序分配全题库连续编号；编号不是目标身份。
- 无复合结构的题目默认以题目自身为一个目标；返回空列表表示没有待答目标。
- 固定提示不进入待答目标列表。主观题即使未评分，也仍应列出待答目标。
- 应用将当前题目的编号映射加入 `navigation.targets`，元素为 `{id,number,label}`，拓展用同一编号显示内部题号。
- 点击大纲时应用加载对应题目，并传入 `navigation.targetId`；已经在同一题目时仅更新定位，不重建页面。
- 增删小题、修改提示或移动整题后，应用在接受更新后重新计算编号。
- 历史存储并使用当时的目标身份、顺序及编号映射，不用新版拓展重新解释历史顺序。
- 样例题库展示须区分题目数量（题卡／数据记录数）和待答小题数量，不能把一张五小题阅读题标成仅一道待答题。

## 10. 错误约定

| 错误码 | 含义 | 页面处理 |
| --- | --- | --- |
| `EXTENSION_MISSING` | 未安装对应拓展 | 应用保留数据并显示安装提示 |
| `VERSION_UNSUPPORTED` | 拓展、数据或协议版本不兼容 | 提示兼容问题，不擅自改写题目 |
| `INVALID_REQUEST` | 字段、操作名或参数不合法 | 修正请求 |
| `DATA_INVALID` | 题目／答案／规则结果未通过检查 | 显示字段问题，保留输入 |
| `SCORE_INVALID` | 非有限数值、越界或小题聚合不合法 | 不记录错误分数 |
| `CONTEXT_EXPIRED` | 旧页面或已离开的对象 | 停止旧回调，等待有效上下文 |
| `REVISION_CONFLICT` | 数据版本冲突 | 保留本地输入，显示冲突，不直接覆盖 |
| `READ_ONLY` | 历史、预览或冻结答案不可写 | 禁用相应操作 |
| `PERMISSION_DENIED` | 未授予该能力 | 显示原因，不重试越权操作 |
| `ACTION_UNAVAILABLE` | 边界、状态或平台不支持 | 按上下文禁用按钮 |
| `RESOURCE_UNAVAILABLE` | 引用失效、缺失或不可访问 | 显示占位错误，不丢弃其他内容 |
| `STORAGE_FAILED` | 持久化失败 | 保留输入，不继续依赖保存的操作 |
| `RENDER_FAILED` | 拓展渲染失败 | 应用提供统一错误和重载入口 |
| `TIMEOUT` | 请求未在期限内获得结果 | 不假定回滚，按相同请求身份恢复查询 |

## 11. 首轮覆盖的功能

- 单选、多选、判断：普通题干／选项、富文本解析、保留选择、正误反馈。
- 完形：富文本标记、正文与下方选项同步、重复标记同步、逐空评分和大纲定位。
- 阅读：文章及小题富文本、普通选项、自适应排布、逐题结果。
- 排序：提示位置、提示字母不可重选、普通字母可重复选、逐位置反馈、只编号待答位置。
- 翻译：自动标记编号画线、句子与答题区对应、独立富文本译文及参考。
- 作文：富文本题干／正式答案／解析、固定格式输入、格式工具开关、未评分状态。
- 所有题型：编辑与练习、历史快照、默认白板、导航、最终得分统计。

应用保留的范围包括工作区、标签栏、历史列表、默认导航、白板组件和最终统计。拓展不拥有任意应用窗口、文件系统、网络或数据库访问能力。

## 12. 待确认的产品选择

| 问题 | 建议方向，尚未视为已确认 |
| --- | --- |
| 编辑保存 | 临时编辑与正式保存分开；切题保留临时编辑，显式保存才落盘。整库落盘如何承载单题保存需明确 |
| 删除确认 | 应用统一提供一次确认，避免默认按钮和拓展重复确认 |
| 未提交时重试 | 保存为明确的未提交／放弃记录，不伪造评分；或仅允许已提交后重试 |
| 空答案提交 | 题型声明是否允许；允许时确认未完成情况，并按规则计分或未评分 |
| 后续评分修订 | 是否允许已评分结果覆盖，以及是否保留修订记录 |
| 最终统计 | 建议显示已得分／总满分及未评分数量，不将未评分隐式计零 |
| 初始几何 | 对齐、坐标、宽高允许哪些字段，默认铺满浏览区还是按内容定位 |
| 页面能力声明位置 | 清单提供默认值，页面可在加载完成时声明；是否允许运行中改变需明确 |

上述选择影响正式接口语义，需先确认后再实施；本草案不要求立即修改题库、数据库或已安装拓展。

## 13. 拓展随附样例题库

### 13.1 用途和目录

每个声明的题型至少提供一份样例题库，每份可以包含一道或多道题。`default.json` 是新建题目的模板，样例题库是实际可加载的内容，两者分别声明，不自动互相覆盖。

```text
my-question-type/
├── manifest.json
├── default.json
├── editor.html
├── practice.html
├── type.js
├── style.css
└── examples/
    ├── basic.qbank
    └── advanced.qbank       可选
```

`.qbank` 沿用现有真实题库包格式，包含 `bank.json`、`manifest.json` 和必要的资源文件；不能将普通 JSON 改后缀冒充题库。文档及已支持的内嵌资源需要自包含，不引用开发者电脑绝对路径或要求外网下载。

### 13.2 声明方式（拟定，尚未实现）

在 `manifest.json` 对应的 `types[]` 条目中增加 `examples`：

```json
{
  "id": "publisher.example",
  "examples": [
    {
      "id": "basic",
      "title": "基础示例",
      "description": "展示题干、答题和解析功能",
      "path": "examples/basic.qbank"
    },
    {
      "id": "advanced",
      "title": "复合交互示例",
      "description": "展示多个小题、定位和部分得分",
      "path": "examples/advanced.qbank"
    }
  ]
}
```

上面的片段只说明 `examples` 字段，并非完整的可安装清单。样例 ID 在所属题型中唯一；路径为包内相对路径。基础题型可只提供基础示例，不强制提供高级示例。

题目数量、小题数量、文件大小、内容哈希由构建／校验工具计算，避免作者手填后失真。每份样例必须含所属题型；首轮建议只使用本包提供的题型，不引入其他拓展依赖。

### 13.3 应用及未来题型库如何使用

| 场景 | 行为 |
| --- | --- |
| 拓展详情 | 显示名称、说明、题目数及待答小题数 |
| 只读预览 | 应用读取样例题库，仍通过相同 `onLoad` 入口传数据，复用 `practice.html` |
| 本地开发验收 | 在隔离的测试会话中打开样例，核对编辑、提交、重试、导航和历史；允许写入只限测试数据 |
| 用户导入 | 用户选择后复制为自己的题库；不修改拓展包中的原样例 |
| 未来题型库／Hub | 展示列表、读取样例并提供下载；复用同一题型和数据版本规则 |

安装拓展不自动向用户工作区添加题库或生成作答记录。用户修改导入副本不改变原样例；拓展升级也不覆盖用户副本。

网页题型库仍只考虑预览，不要求实现网页编辑、练习存储或白板。网页缺少白板宿主能力时不显示切换入口，不改变桌面默认启用的约定。

### 13.4 打包、校验与实施顺序

打包和安装工具需要明确识别 `examples`，检查路径、题库结构、Schema、数据版本、资源引用、类型依赖和包体积。样例题库作为数据读取，不作为可执行脚本注入页面。未来网页预览构建需要按现有资源访问边界生成可读取数据，不能直接绕过应用权限加载整个拓展目录。

实施顺序：

1. 确认本草案的接口及样例题库约定，并明确第 12 节影响保存流程的产品选择。
2. 完成公共接口、生命周期及样例声明的支持，保留现有数据与版本边界。
3. 先使用基础选择题、复合阅读、富文本作文验证全流程，再迁移其余题型。
4. 给所有现有题型补充样例题库，确保新建模板和样例都能独立加载。
5. 使用样例检查无需修改题型专属宿主代码，再作为未来题型库内容来源。

本轮先整理约定；独立图片和视频公共接口、完整题型库网站不进入本轮实施范围。
