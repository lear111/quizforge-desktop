# QuizForge 题型设计说明

> 当前迁移状态（2026-10-07）：八种题型均为独立 HTML 扩展，最新包要求 SDK 2.3；判断题包为 2.3.1，其余为 2.3.0。接口以 [现行参考](../extensions/SIMPLE_PAGE_API.md) 为准，旧题库兼容见 [迁移记录](../extensions/READING_TYPES_MIGRATION.md)。下文是产品功能核对要求，不用于另定义 SDK。判断题作为通用风格与注释模板，见 [模板说明](../extensions/QUESTION_TEMPLATE.md)。

产品要求基线：2026-10-06；文档入口与接口状态更新：2026-10-07。

本文规定各题型的内容格式、编辑方式、作答交互及结果展示，用于后续开发和核对题卡功能。它是产品设计要求；当前实现与要求不一致的地方在文末单独列出，不代表已经完成。

## 1. 内容格式与通用要求

### 内容格式

- **富文本**：支持字体、字号、颜色、加粗、斜体、下划线、段落对齐、首行缩进、表格和图片。保存后应保留格式，练习及历史中使用只读渲染。
- **普通文本**：允许文字和换行，不提供字体、颜色等格式编辑。
- **富文本输入**：用于用户的正式答案。默认按固定格式直接输入；开启“编辑格式”后才显示格式工具，关闭工具后保留已设置的格式。
- **标准答案**：用于判分的选项 ID、字母顺序等结构化数据。它与作者填写的“答案与解析”说明是两份内容，不应依赖解析文字判分。
- **白板草稿**：笔迹、直线、矩形、自由文本及纸张设置。白板草稿独立于正式答案，不作为判分输入。

### 格式总览

| 题型 | 题干／文章 | 小题题干 | 选项 | 正式答题区 | 参考答案／答案与解析 |
| --- | --- | --- | --- | --- | --- |
| 单选题 | 普通文本 | 无 | 普通文本 | 单选按钮 | 标准答案为单个选项；答案与解析为富文本 |
| 多选题 | 普通文本 | 无 | 普通文本 | 复选框 | 标准答案为选项集合；答案与解析为富文本 |
| 判断题 | 普通文本 | 无 | 固定“正确／错误” | 两项单选 | 标准答案为单个选项 ID；答案与解析为富文本 |
| 作文题 | 富文本 | 无 | 无 | 富文本输入 | 富文本 |
| 完形填空 | 富文本，包含 `{{1}}` 等空位标记 | 空位编号 | 普通文本，每空一组选项 | 正文空位选择＋下方单选按钮 | 标准答案为逐空选项；答案与解析为普通文本 |
| 阅读理解 | 富文本 | 富文本 | 普通文本，每小题一组选项 | 每小题单选按钮 | 标准答案为逐题选项；答案与解析为富文本 |
| 段落排序 | 富文本，包含全文及 A–H 段落 | 八个顺序位置 | A–H 普通字母；段落内容放在富文本题干中 | 八个字母选择槽，三个为已给出的提示 | 标准答案为完整顺序；答案与解析为富文本 |
| 翻译题 | 富文本，包含 `{{需要翻译的句子}}` 标记 | 按标记生成编号及句子 | 无 | 每句独立译文输入，目标为富文本输入 | 每句参考译文及整题解析为富文本 |

### 通用题卡行为

1. 编辑、练习、提交结果和历史回放应完整保留该题型要求的内容与交互。
2. 提交答案需要二次确认；有未完成的小题时，应提示未完成数量。
3. 提交后正式答案和本次草稿冻结；重试从新的空白作答开始，保留之前的提交记录。
4. 结果展示统一使用得分和总分。保留作者提供的答案与解析，不额外堆叠重复答案清单。
5. 单选／多选提交后仍保留用户选中的圆点／勾选；颜色反馈用于区分正确答案和错误选择。
6. 题目大纲按需要作答的小题连续编号。移动任意小题编号，移动的是它所在的整张题卡，同时更新题库顺序和大纲编号。
7. 同一题卡的练习模式和草稿模式共用题卡、答案状态和白板内容；切换模式不能丢失笔迹，也不能重建一份独立答案。
8. 练习模式固定视口，隐藏白板工具，保留可见笔迹；草稿模式可以拖动、缩放和使用白板工具。
9. 历史记录也共用上述两种显示视图，但正式答案、笔迹和白板文本均只读。题目、答案、解析、资源和草稿应取自归档快照。
10. 练习及历史的最后一页均提供得分统计卡，背景与前面的练习视图一致，并可返回最后一道题。

## 2. 单选题（SINGLE_CHOICE）

### 编辑要求

- 题干使用普通文本，允许换行，不提供图片、表格及文字格式编辑。
- 每个选项使用普通文本，显示字母标签与选项内容；允许增删选项。
- 正确答案通过选择选项设置，只能有一个正确选项。
- 答案与解析使用富文本，可包含带格式的说明、图片和表格，通过独立的编辑入口修改。
- 已有富文本题干、选项按普通文字显示；仅在作者编辑相应字段后保存为普通文本，打开题库不自动改写原文件。

### 作答与结果

- 用户通过单选按钮选择；重新点击其他选项可更改答案。
- 提交后按所选选项判分：正确取得本题分值，错误不得分。
- 结果保留用户选中的圆点，正确选项使用绿色反馈，错误选择使用红色反馈。
- 大纲中占用一个作答编号。

## 3. 多选题（MULTIPLE_CHOICE）

### 编辑要求

- 题干和选项使用普通文本；答案与解析使用富文本。
- 已有富文本题干、选项的兼容处理与单选题相同。
- 每个选项通过复选框设置是否为正确答案，标准答案为多个选项的集合。

### 作答与结果

- 用户可以勾选或取消勾选多个选项。
- 提交后按答案集合判分；当前规则为完全匹配才取得本题分值，漏选或错选不得分。
- 提交后仍保留勾选状态，并标记正确选项与错误选择。
- 大纲中占用一个作答编号。

## 4. 作文题（ESSAY）

### 编辑要求

- 题干使用富文本，适用于文字要求、书信原文、图画及图表等作文材料。
- 参考答案与解析使用富文本，可包含范文、写作要点和结构说明。
- 小作文和大作文复用同一题型，通过题干、分值及写作要求区分。

### 作答区

- 正式答案使用富文本输入框，不以白板自由文本代替。
- 默认可以直接输入固定格式文字；当前默认格式为 Arial、16px、黑色。
- 默认粘贴为普通文字，避免带入外部软件的异常字体和浅色文字。
- 点击“编辑格式”后才能调整字体、字号、颜色、字形和段落格式；点击“完成编辑”后隐藏工具栏，保留答案格式。
- 开关格式编辑不应清空内容、重建输入框或丢失编辑状态。

### 提交与结果

- 提交后正式答案只读，显示参考答案与解析。
- 当前不自动判定作文质量，提交后为待评分，不能显示为答错或凭空给出分数。
- 历史应保留正式答案的富文本格式和当时的白板草稿。
- 大纲中占用一个作答编号。

## 5. 完形填空（CLOZE）

### 题干与标记

- 文章使用富文本。
- 编辑时用 `{{1}}`、`{{2}}` 等特殊标记表示待填词位置。
- 标记编号对应同一道小题的选项组和标准答案，按编号连续排列。
- 同一个编号重复出现时，代表同一个空位，选择状态同步，只计一次分。
- 需要显示字面标记时可使用转义，例如 `\{{1}}`。
- 本阶段继续使用带编号标记；不把单独的 `{{}}` 当作已实现功能。

示例：

```text
AI can {{1}} human creativity and lead to unique artistic {{2}}.
```

### 选项与答案

- 每个空位提供 A–D 四个普通文本选项。
- 编辑时点击正文空位或下方选项设置正确答案。
- 标准答案保存为每个空位对应的选项。
- 作者填写的答案与解析使用普通文本，可按行描述逐空答案及理由。

### 作答交互

- 练习时隐藏 `{{1}}` 原始语法，显示紧凑的带编号空位，例如 `1._______`。
- 点击正文空位直接弹出该空位的选项；不使用体积较大的原生下拉框挤占文章行高。
- 选择后将选项文本填入正文空位，并与下方单选状态同步。
- 正文空位继承原段落字体、字号和行高；选项弹层悬浮展示，不撑开题卡。
- 下方保留完整小题及选项列表，允许从列表改选。
- 整篇文章统一确认提交，按答对空位数乘单空分值计算得分。
- 提交后显示得分和作者填写的答案与解析，不额外生成一份重复的逐空答案列表。
- 大纲列出全部待答空位；点击编号进入所属完形题卡，并定位对应空位。

## 6. 阅读理解（READING）

### 编辑要求

- 文章使用富文本；每道小题的题干也使用富文本。
- 每道小题提供 A–D 四个普通文本选项，并独立设置正确答案。
- 一篇文章和它的小题组成一张题卡，通常为五道小题，可增删小题。
- 答案与解析使用富文本，允许用表格展示答案并按段说明解析。

### 作答与布局

- 文章下方依次显示小题，每道小题独立单选。
- 四个选项按空间自适应：一行四列 → 两行两列 → 四行一列。
- 当两列布局仍使选项文字折行时，应改为一列，不只按窗口宽度决定布局。
- 选择时不在整道小题外添加额外边框，使用选项行高亮和圆点反馈。
- 整篇阅读统一确认提交，按答对小题数乘单题分值计算得分。
- 提交后保留用户选择标记及对错颜色，显示答案与解析。
- 大纲列出每道小题，点击后进入所属文章并定位对应小题。

## 7. 段落排序（MATCHING）

### 题干与编辑

- 题干使用富文本，直接输入说明和 A–H 八段材料。
- 不要求在正文插入空位标记，也不另外维护一套段落选项富文本框。
- 答案编辑区提供八个顺序位置，各位置选择一个 A–H 字母，完整标准答案必须构成八个字母的排列。
- 通过编辑区的锁定操作将某个位置设为“已给出的提示”；当前规格为三个提示位置、五个待答位置。
- 锁定的是“位置及该位置的提示字母”。提示不计分，也不占作答编号。
- 答案与解析使用富文本。

### 作答交互

- 显示八个顺序槽，空间足够时排列在同一行，较窄视口适当换行。
- 提示槽直接显示已给出的字母，不可改选；作答时不显示锁图标。
- 其余槽通过简洁的字母选择控件作答，不显示选后清空的 X 按钮，可继续改选。
- 普通待选字母可以在多个位置重复选择，由用户自行判断；不能因为某字母已经选过就自动禁用它。
- 已作为锁定提示的字母不能再供待答槽选择。
- 提交后逐个待答槽标记正确或错误；未填写的待答槽也应显示未答／错误反馈。提示槽保持提示样式。
- 得分仅累计五个待答位置，不包含三个提示位置。
- 大纲只列出需要作答的位置，提示位置不编号；编辑改变提示位置后应更新待答编号，当前保存规则仍要求恰好三个提示。

## 8. 翻译题（TRANSLATION）

### 题干与标记

- 文章使用富文本，用 `{{需要翻译的句子}}` 标记目标句子。
- 不在标记内手写题号，按句子在正文中出现的顺序自动生成编号。
- 预览和练习时隐藏花括号，给目标句子加下划线并显示题号。
- 通常标记五句；句数可以变化，至少有一句。
- 不允许空标记、嵌套标记或缺失结束符；字面花括号可使用转义。

示例：

```text
The author explains the idea. {{Technology changes the way we learn.}} The discussion continues.
```

### 答题区与参考答案

- 文章下方按编号提供每句独立译文输入，不把五句答案混在一个输入框中。
- 译文输入目标为富文本输入：默认固定格式作答，打开格式编辑后可调整格式。
- 每句参考译文使用富文本，整题答案解析也使用富文本。
- 标记句子、答题框和参考译文需要保持对应关系；修改或新增句子后不能把旧参考译文误挂到其他句子上。

### 提交与结果

- 整道翻译题统一确认提交；缺少译文时提示未完成的句数。
- 当前提交为待评分，不将空的评分结果显示为零分或答错。
- 提交后译文只读，显示对应参考译文及解析。
- 大纲按待翻译句子连续编号，点击后定位对应句子或译文区域。

## 8.1. 判断题（TRUE_FALSE）

- 题干使用普通文本，保留换行；“正确／错误”两项固定，不能增删或修改。
- 编辑时选择一个正确答案，设置正数分值，使用富文本填写答案与解析。
- 作答时两项并排，窄屏改为两行；提交前行内确认，按是否匹配标准答案给满分或零分。
- 提交后保留选中圆点，同时通过颜色与文字区分正确答案和错误选择；结果区显示得分及解析。
- 练习、草稿及历史使用同一练习页面；历史禁止修改并隐藏提交、重试。
- 大纲占用一个作答编号。复制时重新分配题目与选项 ID，并同步正确答案引用。

## 9. 当前实现与设计要求的差异

| 项目 | 当前实现 | 本文要求／后续核对点 |
| --- | --- | --- |
| 完形答案与解析 | 新拓展按普通文本编辑和显示；旧富文本解析仍可读取 | 已按要求迁移，打开文件不自动改写 |
| 翻译正式答题区 | 每句富文本输入，与作文共用格式编辑开关 | 已补齐文字格式输入与只读回放 |
| 主观题输入图片、表格 | 已有答案可保留、显示；尚无新图片上传和表格插入按钮 | 后续通过受限公共能力补齐插入操作 |

后续修改题型时，以本文的内容格式和交互要求核对编辑、练习、结果及历史四个入口。详细代码与数据协议分别见 [新人技术指南](new-developer-guide.md)、[题库文件格式](qbank-format.md) 和 [统一练习架构](../quizforge-desktop-app/editor-web/draft-canvas/SHARED_LEARNING_SURFACE.md)。
